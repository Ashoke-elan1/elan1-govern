Completeness check — L1, L2, L3 and Sovereign

28 October 2026, evening. Nothing was built or changed for this check. It covers the console, the receipt verifier, the developer portal, the counterparty, regulator and partner portals and the status page. The public site is not included: it is already built.

How it was checked.
  • Code reviews. Five reviewers each read one area of the code against the approved plan and the digests of the Information Memorandum, Technology Memorandum, Architecture Atlas and financial model. Each re-checked the gaps listed in the morning check (07-completeness-check.md).
  • Static link check. Every link target in the code was matched against the routes.
  • Live crawl. Every link was followed in the running app, signed in as each level's owner.
Not counted:
  • The refusal price. 40% of the per-action rate is the rule. It is deliberate and is not stated in the documents.
  • The decisions in 08-conflict-decisions.md. They are built, and are not reported as conflicts.
  • Items the memorandum marks LATER.
  • The partner programme, backend internals and separate products.

6. Built since the morning check

  • L1 copy. L1 copy says "sealed in a hash chain"; L2 and above say "signed".
  • Autonomy. Graduation only. A2 is the starting level, A3 comes by a two-person graduation with 30-day supervision, revoke is one press, and A4/A5 are shown as not yet available.
  • Approvals. One declared 24-hour extension.
  • Verifier. A batch timestamped by one authority is reported as degraded, not failed.
  • Packs. They install at L1 as an unbilled dry run, and checks that need L2 evidence read not applicable.
  • Erasure is available from L1 on /records/erasure. A test erasure kept the chain verifying.
  • Counterparty register. Listed read-only from L1.
  • Billing. The verifier profile is billed as its own line; each L2+ bundle is ₹2,500 and the L1 auditor pack is free.
  • Keys. Agent keys are gk_ and sk_sbx_.
  • README. The two-step code text is now correct.
